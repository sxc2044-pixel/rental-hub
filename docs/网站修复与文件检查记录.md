# 网站修复与文件检查记录

检查日期：2026年10月24日。

网站现已恢复：http://127.0.0.1:8080 。Java服务在Windows本机运行，连接Kali的192.168.93.128:3306/rental，实际服务器版本为11.4.5-MariaDB-1，使用MySQL兼容协议。Navicat中的“kali”是连接名称，不是当前项目数据库名称；刷新该连接后应查看rental。

## 故障原因和修复

浏览器拒绝连接的直接原因是本机8080没有Java进程监听。数据库新连接约10.5秒才返回握手，超过原配置10秒读取超时，导致Spring Boot初始化数据源失败后退出；早期只读诊断超时甚至只有5秒。

已将JDBC读取超时调整为30秒、连接超时10秒、连接池等待30秒，并设置最少空闲连接2个。修复后的启动约需12至15秒，必须保留Java服务，单独打开Kali或Navicat不会自动启动网站。没有修改数据库全局DNS或授权设置；skip_name_resolve=0只是观察结果，不将DNS断言为已证实的等待原因。

## 数据库迁移和旧库清理

原项目库kali的10张表、结构、索引及全部记录已迁移至rental；迁移时逐表比较记录数及完整行内容SHA256，全部一致。验证完成后删除旧kali，完成数据库更名。

rental_db是一套不同结构的旧示例库，当前项目没有引用。实际包含1个初始化管理员、12条房源、14条字典和1条公告，预约、合同、评价、咨询等业务记录均为0。先导出完整SQL及SHA256，再经用户明确回复“确认删除旧 rental_db”后删除。
